# ZAMIN FK Management — Project Memory

This folder is the independent written memory and source of truth for the ZAMIN FK management-game project. It is separate from the Telegram Mini App, its code, database, bot and existing project memory. It is documentation, not a runtime dependency.

## Documents
- PROJECT_IDENTITY.md — what the game is and is not.
- GAME_CONCEPT.md — gameplay systems and loop.
- APPROVED_DECISIONS.md — only owner-approved decisions.
- OPEN_QUESTIONS.md — unresolved decisions.
- DEVELOPMENT_HISTORY.md — dated direction and progress record.
- CURRENT_STATUS.md — current phase and next work.
- WORKING_RULES.md — memory and repository safety rules.

## Labels
APPROVED = explicitly accepted by owner. PROPOSED = suggested, not accepted. OPEN = undecided or needs testing. REJECTED = explicitly declined. IMPLEMENTED / UNVERIFIED = exists but is not tested. VERIFIED = tested with evidence.

Suggestions and implementations do not become approvals automatically.

## Authority
1. The latest explicit owner instruction takes priority.
2. Record changes to earlier decisions in DEVELOPMENT_HISTORY.md.
3. Keep proposals separate from approvals.
4. Preserve ambiguity rather than inventing certainty.
5. Do not import assumptions from the existing Mini App or community project.

Core principle: the game's written memory is independent of the Mini App. Future interfaces are access methods, not the source of project identity or memory.
